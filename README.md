# ربات ترید — از صفر

> 🟡 **دستیار ترید طلا برای متاتریدر ۴ (GoldPilot Recovery v4)** در پوشه
> [`mt4/`](mt4/) است — راهنمای نصب، سیاست مدیریت سبد و هشدارهای ریسک در
> [`mt4/README.md`](mt4/README.md). بقیه این صفحه درباره ابزار پایتونی
> بک‌تست کریپتو است.

اسکلت یک ربات معاملاتی کریپتو به زبان پایتون، همراه با موتور بک‌تست و
حالت معامله با پول تقلبی.

> ⚠️ **این ربات سودده نیست و قرار هم نیست باشد.**
> این یک *ابزار یادگیری و اندازه‌گیری* است. استراتژی داخلش یک نمونه
> کلاسیک و ساده است. کار تو این است که با این ابزار، استراتژی‌های خودت
> را بسازی و — مهم‌تر — بی‌رحمانه تستشان کنی.

## چرا این تصمیم‌ها گرفته شد؟

تو گفتی تهران هستی، تجربه قبلی نداری، و انتخاب را به من سپردی. این‌ها
انتخاب‌های من و دلیلشان است:

| موضوع | انتخاب | چرا |
|---|---|---|
| **بازار** | کریپتو | API باز و رایگان، ۲۴ ساعته، داده تاریخی فراوان. بورس ایران API رسمی ندارد و برای شروع کار را سخت می‌کند. |
| **زبان** | پایتون | اکوسیستم تحلیل داده بی‌رقیب. برای این کار استاندارد صنعت است. |
| **تایم‌فریم** | کندل ۴ ساعته | معامله در تایم‌فریم پایین (۱ دقیقه‌ای) یعنی جنگ با ربات‌های حرفه‌ای روی سرعت — بازیِ ما نیست. در ۴ ساعته کارمزد کمتر اهمیت دارد و سرور کند هم مشکلی ایجاد نمی‌کند. |
| **سبک** | سوئینگ (چند معامله در ماه) | کمتر معامله = کمتر کارمزد = کمتر اشتباه. برای شروع بهترین است. |
| **صرافی داده** | نوبیتکس | از داخل ایران بدون فیلتر در دسترس است و برای گرفتن قیمت نیازی به کلید API ندارد. بایننس IP ایران را مسدود می‌کند. |
| **اجرای سفارش** | فقط کاغذی | اتصال به حساب واقعی **عمداً** پیاده‌سازی نشده. تا نتیجه چند ماه معامله کاغذی را ندیده‌ای، این در نرم‌افزار قفل است. |

## نصب و اولین اجرا

```bash
# ۱) محیط مجازی بساز (تا بسته‌ها با سیستم قاطی نشوند)
python3 -m venv .venv
source .venv/bin/activate        # در ویندوز: .venv\Scripts\activate

# ۲) وابستگی‌ها را نصب کن
pip install -r requirements.txt

# ۳) پروژه را نصب کن
pip install -e .

# ۴) ببین همه‌چیز سالم است
python -m trading_bot doctor
```

اگر `pip install -e .` به مشکل خورد، بدون نصب هم می‌شود اجرا کرد:

```bash
PYTHONPATH=src python -m trading_bot doctor
```

### اولین بک‌تست (بدون نیاز به اینترنت)

```bash
python -m trading_bot backtest --source sample --limit 1500
```

`sample` داده‌ی مصنوعی می‌سازد — ارزش تحلیلی ندارد، فقط برای این است که
همین الان ببینی ربات چطور کار می‌کند.

### بک‌تست روی داده واقعی

```bash
python -m trading_bot fetch --source nobitex --symbol BTCUSDT --timeframe 4h --limit 1000
python -m trading_bot backtest --source nobitex --symbol BTCUSDT --timeframe 4h
```

### معامله کاغذی (پول تقلبی)

```bash
python -m trading_bot paper --reset          # شروع با حساب صفر شده
python -m trading_bot status                 # دیدن وضعیت حساب
```

## دستورها

| دستور | کار |
|---|---|
| `doctor` | بررسی محیط و اینکه به کدام صرافی دسترسی داری |
| `fetch` | دانلود و ذخیره کندل‌ها در `data/cache/` |
| `backtest` | اجرای استراتژی روی داده گذشته + گزارش کامل |
| `optimize` | جست‌وجوی پارامترهای بهتر (خطرناک — پایین‌تر بخوان) |
| `paper` | اجرای زنده با پول تقلبی |
| `status` | وضعیت فعلی حساب کاغذی |

`python -m trading_bot <دستور> --help` جزئیات هر کدام را می‌دهد.

## استراتژی نمونه چه می‌کند؟

```
می‌خریم وقتی:
   میانگین ۱۲ از پایینِ میانگین ۲۶ به بالا عبور کند   (شروع حرکت صعودی)
   و قیمت بالای میانگین ۲۰۰ باشد                       (روند کلی صعودی است)

می‌فروشیم وقتی:
   میانگین ۱۲ به زیر میانگین ۲۶ برگردد، یا
   قیمت به حد ضرر برسد   (۲.۵ × ATR زیر قیمت ورود)، یا
   قیمت به حد سود برسد   (۵.۰ × ATR بالای قیمت ورود)
```

شرط دوم ورود مهم‌ترین قسمت است: تقاطعِ تنها، در بازار خنثی سیگنال‌های
دروغینِ پشت‌سرهم می‌دهد و کارمزدها حساب را می‌خورند.

**مدیریت ریسک** (مهم‌تر از خود استراتژی):

```
حجم معامله = (سرمایه × ۱٪) ÷ فاصله حد ضرر
```

یعنی حجم را طوری حساب می‌کنیم که اگر حد ضرر بخورد، دقیقاً ۱٪ سرمایه از
دست برود — نه بیشتر. در بازار پرنوسان خودبه‌خود حجم کمتری می‌گیریم.
با این فرمول، ۱۰ باخت پشت سر هم هم فقط ~۱۰٪ حساب را می‌برد.

## چطور نتیجه بک‌تست را بخوانم؟

| معیار | معنی | مقدار قابل قبول |
|---|---|---|
| **بازده کل** | کل سود/زیان | باید از «بخر و نگه دار» بیشتر باشد، وگرنه ربات ارزشی ندارد |
| **بیشترین افت سرمایه** | بدترین افت از سقف | زیر ۲۰٪ خوب، بالای ۳۰٪ غیرقابل تحمل |
| **نسبت شارپ** | بازده به ازای ریسک | بالای ۱ خوب، بالای ۲ عالی، زیر ۰ بد |
| **ضریب سوددهی** | مجموع سودها ÷ مجموع ضررها | بالای ۱.۵ |
| **تعداد معاملات** | — | زیر ۳۰ معامله، نتیجه آماری بی‌معناست |

**نکته‌ای که همه از قلم می‌اندازند:** اگر بازده رباتت ۲۰٪ است ولی
«بخر و نگه دار» ۸۰٪ بوده، رباتت شکست خورده — با همه پیچیدگی‌اش،
از خریدن ساده و نشستن بدتر عمل کرده.

## تله‌هایی که باید بشناسی

### ۱. نگاه به آینده (Look-ahead bias)
شایع‌ترین دلیل بک‌تست‌های دروغین. اگر ربات هنگام تصمیم‌گیری روی کندل
فعلی، از قیمت *بسته شدن* همان کندل استفاده کند، دارد از اطلاعاتی استفاده
می‌کند که در آن لحظه نداشته. نتیجه: بک‌تستِ درخشان، ضررِ واقعی.

این پروژه سیگنالِ هر کندل را روی قیمت *باز شدنِ کندل بعد* اجرا می‌کند و
یک تست اختصاصی هم برایش دارد (`test_entry_fills_on_next_bar_open...`).

### ۲. بیش‌برازش (Overfitting)
دستور `optimize` را اجرا می‌کنی، بهترین پارامتر را پیدا می‌کنی، ذوق‌زده
می‌شوی. ولی آن پارامترها فقط روی *همان داده* خوب بوده‌اند — مثل حفظ کردن
جواب‌های یک آزمون به‌جای یادگیری درس.

**راه‌حل:** داده را دو تکه کن. روی نصف اول بهینه کن، روی نصف دوم (که هرگز
ندیده‌ای) تست کن. اگر آنجا هم خوب بود، شاید واقعی باشد.

### ۳. کارمزد و لغزش قیمت
استراتژی‌ای که بدون کارمزد ۳۰٪ سود می‌دهد، با کارمزد ۰.۱٪ و ۲۰۰ معامله
در سال، ۱۰٪ ضرر می‌دهد. این پروژه هر دو را در همه محاسبات اعمال می‌کند.

### ۴. داده خراب
یک کندل غلط یا گم‌شده می‌تواند کل نتیجه را عوض کند. `data/base.py` هر
کندل را قبل از استفاده اعتبارسنجی می‌کند.

## مسیر پیشنهادی

```
✅ مرحله ۱  محیط را راه بینداز و کد را بخوان        → همین الان
✅ مرحله ۲  با sample و nobitex بک‌تست بگیر          → امروز
   مرحله ۳  پارامترها را در config.yaml عوض کن،
            ببین نتیجه چطور تغییر می‌کند             → این هفته
   مرحله ۴  استراتژی خودت را در strategy/ بنویس      → این ماه
   مرحله ۵  paper را ۲۴ ساعته روی VPS اجرا کن        → ۱ تا ۳ ماه
   مرحله ۶  نتیجه واقعی را با بک‌تست مقایسه کن       → بعدش
   مرحله ۷  فقط اگر مرحله ۶ قانع‌کننده بود:
            با کمترین پول ممکن، واقعی شو
```

**از مرحله ۵ نپر.** تفاوت نتیجه معامله کاغذی با بک‌تست، تنها چیزی است که
به تو می‌گوید بک‌تستت دروغ می‌گفته یا نه.

## سرور مجازی (VPS)

تا مرحله ۴ لازم نیست؛ روی لپ‌تاپ خودت کار کن.

از مرحله ۵ که ربات باید ۲۴ ساعته بیدار باشد، یک VPS ارزون (~۵ دلار در ماه،
مثل Hetzner یا Contabo) کافی است. اجرای دائم با `systemd` یا `screen`:

```bash
screen -S bot
python -m trading_bot paper
# Ctrl+A بعد D برای خارج شدن بدون بستن ربات
```

## امنیت — این بخش را جدی بگیر

- 🔒 فایل `.env` **هرگز** کامیت نمی‌شود (در `.gitignore` است). کلید API را
  مستقیم داخل کد ننویس.
- 🔒 وقتی در صرافی API Key می‌سازی: دسترسی **برداشت (Withdraw) را خاموش کن**.
  اگر کلیدت لو برود، حداکثر ضرر معامله بد است، نه خالی شدن حساب.
- 🔒 IP سرورت را در لیست مجاز صرافی بگذار.
- 🔒 اگر روزی حالت واقعی را اضافه کردی، اول با کمترین مبلغ ممکن.

## قدم‌های بعدی که می‌توانی اضافه کنی

- استراتژی‌های بیشتر در `src/trading_bot/strategy/` (RSI، بریک‌اوت، بازگشت به میانگین)

- اعلان تلگرام هنگام باز/بسته شدن پوزیشن
- پشتیبانی از چند نماد به‌طور همزمان
- حد ضرر متحرک (Trailing Stop)
